## Executive summary
The project is in good shape for a single-file app: clear flow, good user-facing options, and passing tests for sharpness behavior. The biggest issues are around dependency/packaging reliability and edge-case routing logic for video-only events. Documentation is generally strong, but there are a few inconsistencies and missing contributor-oriented sections.

## Prioritized findings (bugs/risks)

### High

1. Missing runtime dependency for advertised sharpness feature
- Evidence:
  - `README.md:53` lists `opencv-python` as a dependency.
  - `requirements.txt` currently includes only `speciesnet` and `customtkinter`.
  - `trailcam_sorter.py:144` uses `cv2` in `score_sharpness`.
- Impact:
  - Users installing from source via requirements may not have OpenCV.
  - `--sharpest` can silently degrade (all scores become 0.0), producing non-sharpness behavior without warning.
- Recommendation:
  - Add `opencv-python` to `requirements.txt`.
  - Add a runtime warning when `--sharpest` is enabled but `cv2` import fails.

2. Build script is machine-specific and likely fails on other developer machines
- Evidence:
  - `installer/build.ps1:10-11` hardcodes `C:\Users\Tim\Miniconda3\...` paths.
- Impact:
  - Packaging process is not portable; onboarding and CI/CD packaging are blocked.
- Recommendation:
  - Resolve Python/PyInstaller dynamically (for example via `Get-Command` or environment variables).
  - Allow overrides via script parameters (`-PythonExe`, `-PyInstallerExe`, `-InnoExe`).

### Medium

3. Video-only event matching by minute is ambiguous in multi-species bursts
- Evidence:
  - `trailcam_sorter.py:237-244` stores one species per minute (`minute_species[ek[:13]] = sp`).
  - `trailcam_sorter.py:255` uses that single minute mapping for video-only events.
- Impact:
  - If two different species occur within the same minute, a video-only event may get the wrong label.
- Recommendation:
  - Replace minute-wide map with nearest-neighbor matching by timestamp delta, with a configurable max gap (for example 30-90 seconds).
  - If multiple candidates tie or confidence is low, route to `Review`.

4. Dry-run output can misrepresent filename collisions
- Evidence:
  - `trailcam_sorter.py:291` collision detection depends on `dst.exists()`.
  - In dry-run mode (`trailcam_sorter.py:295`), files are not created, so same-run collision increments may not be reflected accurately.
- Impact:
  - Dry-run may claim destination filenames that would be suffixed in real mode.
- Recommendation:
  - Maintain an in-memory set of reserved destination paths during one run, used in both dry and real mode.

5. Country code example inconsistency in module docstring
- Evidence:
  - `trailcam_sorter.py:14` shows `--country US`.
  - CLI help and README use ISO alpha-3 examples (`USA`).
- Impact:
  - Minor confusion; possible failed geofencing if users copy the wrong example.
- Recommendation:
  - Change example to `--country USA`.

### Low

6. Silent config write/read failures hide useful diagnostics
- Evidence:
  - `trailcam_sorter.py:73-88` catches all exceptions and suppresses them.
- Impact:
  - Harder troubleshooting for permission/path/JSON corruption issues.
- Recommendation:
  - Log at debug level on failure.

7. Test suite currently focused on sharpness path only
- Evidence:
  - `tests/test_sharpness.py` contains 9 tests, all sharpness-related.
- Impact:
  - Regressions in parsing, geofencing argument handling, report schema, and video-only routing may go undetected.
- Recommendation:
  - Add tests for parsing/grouping, routing threshold behavior, report output schema, and video-only matching logic.

## Code improvement suggestions

1. Split core logic and UI for maintainability
- Current: single large file (`trailcam_sorter.py`).
- Suggested modules:
  - `core/events.py` (filename parsing/grouping)
  - `core/classifier.py` (SpeciesNet loading/inference)
  - `core/sorter.py` (copy/move/routing)
  - `core/report.py` (JSON report)
  - `ui/gui.py` and `cli.py`
- Benefit: easier testing, lower risk refactors, better contributor onboarding.

2. Add structured run result object
- Have `run_sort` return a dataclass summary (events, classified count, skipped, review count, elapsed).
- Benefit: easier UI summaries, better tests, and future metrics export.

3. Add explicit validation for option combinations
- Validate `region` only when country is `USA` in CLI path too.
- Emit actionable warnings for invalid country/region format.

4. Improve cancellation responsiveness messaging
- Inference is non-interruptible mid-batch (`run_sort` comment acknowledges this).
- Add status text explaining this clearly in GUI when cancel is requested during inference.

5. Improve logging consistency
- Consider emitting key decisions (representative chosen, route reason) in structured form (JSON-friendly), optionally behind verbose flag.

## Feature opportunities

### High-value near-term
1. Review workflow UI
- Add quick actions to reclassify/move files from `Review` folder in-app.

2. Duplicate event suppression
- Optional hash/perceptual hash to avoid copying near-identical bursts.

3. Resume and checkpointing
- Save progress state and resume long runs after interruption.

4. CSV export
- Export summary/report to CSV for wildlife analysis workflows.

### Mid-term
5. Time-window and camera-aware grouping
- Group by configurable seconds and optional camera ID metadata, not only filename event key.

6. EXIF/video metadata fallback
- Parse capture time from metadata when filenames do not match strict pattern.

7. Confidence policy profiles
- Presets like conservative/balanced/recall for easier threshold tuning.

### Long-term
8. Plugin classifier backend
- Keep SpeciesNet default, but allow alternate models via adapter interface.

9. Lightweight local dashboard
- Filterable run history, species trends, and confidence distributions.
